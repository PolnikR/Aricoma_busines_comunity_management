# 0002. The API layer is generated React Query code

## Status

Accepted, 2026-09-29. Supersedes [ADR 0001](0001-orval-single-source-of-api-contract.md).

## Context

ADR 0001 made the generated zod schemas the source of the contract, but every
feature still wrapped them by hand: API modules, React Query hooks, query keys,
invalidation, rename-only view models and local `SPEC GAP` schemas. A backend change
therefore touched several layers per feature. Design:
`docs/superpowers/specs/2026-09-29-orval-full-integration-design.md`.

## Decision

1. **One generated client.** Orval generates `src/generated/query` with
   `client: 'react-query'`, `httpClient: 'fetch'` and `mode: 'tags-split'`: per
   operation a fetch function, a `useX` hook, `getXQueryKey` and `getXQueryOptions`,
   and zod schemas in `src/generated/query/zod`. The legacy `src/generated/api`
   output is removed.
2. **Spec fixes live in `scripts/orval/specPatches/`.** Each patch targets one place
   in the spec and throws `Spec patch <name> is obsolete` once the backend provides
   the schema, so regeneration fails and the patch is deleted instead of silently
   overriding the backend. Every patch is listed in `docs/api/openapi-spec-gaps.md`.
3. **Readable names.** `scripts/orval/operationName.mjs` derives names from routes:
   `/get_providers` becomes `getProviders`, `PUT /discovery/cache/config` becomes
   `putDiscoveryCacheConfig`. A collision fails the generator.
4. **Runtime validation runs in the mutator.** Orval disables its generated runtime
   validation whenever a custom mutator is set, and the mutator is required (Keycloak
   token, `/api` prefix, `OrvalApiError`). `src/shared/api/validatingMutator.ts`
   therefore validates each response against the registry
   `src/generated/query/responseSchemas.gen.ts`, keyed `'<METHOD> <path>'` and
   generated by `scripts/orval/generate-response-registry.mjs`. A response that does
   not match the spec becomes a query error naming the operation.
5. **Unlisted fields are kept.** Orval emits `zod.object`, which strips keys the spec
   does not list. The mutator merges the parsed value over the received payload
   (`keepUnlistedFields`), so vendor fields such as Airflow's `dag_runs` still reach
   the UI. Listed fields are validated; unlisted ones pass through unvalidated.
6. **Errors are typed as `Error`.** The mutator exports `ErrorType<_Error> = Error`, so
   every generated hook reports `Error` without per-call generics.
7. **Features use backend field names.** Components use the spec's snake_case names.
   A mapper exists only where data is really derived, and runs in the hook's
   `select`. Generated types are `zod.input` while the mutator returns the parsed
   output, so a `select` casts the input type to the `*Output` type where defaults
   make them differ, with a comment at the cast.
8. **Caching.** The global `QueryClient` policy applies to generated hooks. Polling
   and other exceptions are passed through the hook's `query` option. Query keys are
   only the generated `getXQueryKey`. Invalidation after a mutation is declared once
   in `mutationInvalidates` in `orval.config.ts`. Mutations do not write the response
   into the cache with `setQueryData`; the list is refetched instead. This costs one
   extra request per mutation and removes hand-written cache writes.
9. **Facades are the exception, not the rule.** A hand-written hook over generated
   fetchers or query options is allowed only when it carries real logic: composite
   queries (`useQueries`, debounce, forced refresh), or mutations that validate input
   and reshape the response for the page (recovery groups, recovery applications).
   Each is listed with its reason in `eslint.config.js`.
10. **The FlashSystem volume tree is parsed in the feature.** Orval 8.33 generates
    neither recursive schemas nor a `kind`-discriminated union for this spec shape,
    so a spec patch would validate the tree wrongly. The generated schema validates
    the envelope, `infrastructure/helpers/parseVolumeTreeNodes.ts` validates the nodes.
11. **Guards.** ESLint forbids `zod`, `useQuery`, `useQueries` and `useMutation` from
    `@tanstack/react-query`, and `@/generated/api` in `src/features`, except the
    listed files. `scripts/orval/check-feature-layout.mjs`, run by `npm run lint`,
    rejects `*QueryKeys.ts` files and `api/schemas/` folders. The GitLab job
    `api-drift` pulls the backend spec, regenerates and typechecks, and fails when
    the committed snapshot differs.

## Consequences

- A backend change is `npm run api:update` followed by `npm run typecheck`; the
  typecheck points at every use of a changed field.
- A new optional field appears in the data without code changes.
- A patched gap that the backend fixes fails regeneration by name.
- Tests stub `fetch` and assert the real requests, so they cover the generated
  client and the mutator instead of mocks of hand-written modules.
- Not covered by any tool: a field that keeps its name and type but changes meaning.
